## 0.2 Safety-control nets (owner gate 6)

**FLY_EN** (K-10, fail-off). Intended pads, from `scripts/design.py`, sheet "Kill path":
- U301.12 (LM51551 UVLO/EN);
- R401.1 (4.7 k pull-down to GND: fail-off default);
- R402.2 (1 k from MCU_48V_EN, so the supervisor can overpower the main MCU);
- Q401.3 (BSS138 drain; gate = SUP_VETO with the R403 10 k pull-up, so the veto is ON by default);
- TP401.1;
- Q303.1, a DNP PLACEHOLDER level shifter for the undesigned output switch. It is optional until U-06 is decided and will remain an unconnected P item.

Intended levels:
- MCU high: 3.3 V × 4.7 / 5.7 = 2.72 V, so the converter runs.
- Pull-down only, or Q401 on: about 0 V, below the 0.4 V EN minimum (SNVSB75E), so it shuts down.

A completed route proves only copper continuity. It does not prove fail-off behaviour; that still needs SG-03/SG-05 on hardware (bench validation is outside this digital handover).

**HB_S2M** (supervisor to main heartbeat): U601.13 (STM32C031 PA2, USART2_TX) to U501.12 (STM32WBA55 PA1, LPUART1_RX), point to point, with no other parts. The pins were checked against the STM32CubeMX 6.18.1 database (`validation/logs/pinmap_check.md`). Routing it does not prove the heartbeat or timeout logic, which is firmware and needs bench verification.

Neither net is routed in Stage 1.
